1. Visão Geral e Credenciais de Acesso

O SambaCore4 é uma interface web intuitiva e moderna projetada para simplificar a administração centralizada de ambientes Active Directory gerenciados pelo Samba 4 (AD DC). O sistema elimina a necessidade de executar comandos complexos no terminal para tarefas rotineiras, fornecendo dashboards visuais para monitoramento do servidor, inteligência preditiva de segurança e controle total de usuários, máquinas, unidades organizacionais (OUs) e diretivas de grupo (GPOs).

🔑 Credenciais Padrão do Sistema Web:
• Usuário Inicial: admin_master
• Senha Inicial: admin123

2. Estrutura da Interface e Navegação

A interface do painel web foi estruturada para proporcionar uma navegação rápida e fluida entre os seus principais módulos operacionais:

  • Visão Geral: Dashboard principal com dados globais do sistema, estatísticas de hardware e IA defensiva preditiva.
  • Usuários AD: Módulo de administração completa de contas corporativas do domínio.
  • Desktops / Computadores: Controle e inventário de estações de trabalho e servidores.
  • Unidades Organizacionais: Gerenciamento da estrutura hierárquica do diretório LDAP (OUs).
  • Diretivas GPO: Criação, edição e vínculo de objetos de Diretivas de Grupo.
  • Operadores do Sistema: Gestão de acessos e permissões dos operadores ao painel web.
  • Navegador de Objetos: Ferramenta de consulta avançada e detalhada de todos os objetos do diretório.
  • Comandos samba-tool: Console de transparência, logs e execução de comandos CLI.

3. Métricas do Servidor e Hardware

Através do painel Visão Geral, a equipe de infraestrutura pode monitorar continuamente a integridade do servidor Debian Linux:

  • Total de Usuários AD: Quantidade total de contas cadastradas e ativas no samba-tool.
  • Desktops / Computadores: Total de máquinas clientes e servidores ingressados no domínio.
  • Uso de CPU / RAM / Disco: Telemetria detalhada de consumo de hardware do servidor.
  • Rede & Conectividade: Monitoramento de throughput de Download/Upload e testes de latência.

4. Instalação Automatizada e Cópia de Arquivos

Para simplificar o processo de implantação da plataforma no servidor Debian Samba AD, o projeto conta com o script autosserviço install.sh (ou installsmbc4.sh).

Passo 1: Execução do Script Instalador

chmod +x installsmbc4.sh
sudo ./installsmbc4.sh

Passo 2: Cópia Obrigatória de Arquivos do Projeto

Após a finalização da execução do script de instalação, é obrigatório realizar a cópia da pasta de arquivos estáticos, dos scripts Python e do módulo de Inteligência Artificial para o diretório de execução da aplicação:

📁 Arquivos e Pastas a Serem Copiados:
  • Pasta: public/ (Contém os arquivos estáticos, CSS, JS e componentes visuais do painel)
  • Arquivo: server.py (Script principal do servidor web e das rotas da API)
  • Arquivo: samba_service.py (Módulo de integração direta com os comandos do Samba 4)
  • Arquivo: ai_detector.py (Módulo de Machine Learning para análise preditiva de ameaças)

Exemplo do comando de cópia para o diretório final da aplicação (/opt/sambacore4/):

cp -r public/ /opt/sambacore4/
cp server.py /opt/sambacore4/
cp samba_service.py /opt/sambacore4/
cp ai_detector.py /opt/sambacore4/

5. Módulo de Inteligência Artificial e Análise Preditiva de Segurança

O SambaCore4 possui um motor de IA Defensiva integrado responsável por analisar o comportamento do domínio em tempo real e prever riscos potenciais de segurança, como ataques de força bruta, sequestro de sessões ou desvio de comportamento operacional.

Arquitetura e Bibliotecas de Machine Learning

O motor é alimentado pelo arquivo ai_detector.py e requer as seguintes bibliotecas Python instaladas dentro do ambiente virtual (venv) da aplicação:

  • scikit-learn: Fornece algoritmos preditivos e modelos de detecção de anomalias.
  • pandas: Responsável pela manipulação e estruturação temporal dos logs do sistema.
  • numpy: Processamento de matrizes e vetores numéricos de risco.

Parâmetros e Variáveis Avaliadas pelo Modelo

A cada execução da varredura (via botão "Executar Varredura" ou agendamento automático), o modelo processa as seguintes métricas do servidor:

Métrica / Evento Descrição do Diagnóstico
Falhas de Autenticação Mapeia tentativas incorretas de login via NTLM/Kerberos para identificar padrões de Brute Force ou Password Spraying.
Anomalia de Horários Compara acessos e solicitações de autenticação ocorridas fora do horário comercial com o histórico do domínio.
Volumetria de Requisições por IP Detecta picos anormais de tráfego vindos de uma mesma estação de trabalho ou IP da rede local.
Alteração de Contas Privilegiadas Avalia criações de usuários atípicos, resetes de senha repetidos e bloqueios repentinos de contas corporativas.

Interpretando a Pontuação de Risco (Risk Score)

O modelo consolida as anomalias detectadas em uma pontuação normalizada de 0 a 100:

  • 0 a 30 (LOW / Verde): Ambiente estável e seguro. Nenhuma anomalia significativa foi detectada.
  • 31 a 70 (MEDIUM / Amarelo): Alerta moderado. Pequenos desvios detectados (ex: falhas de login pontuais de um usuário).
  • 71 a 100 (HIGH / Vermelho): Alerta crítico. Atividade altamente atípica detectada, indicando potencial ataque ou vetor de ameaça em andamento.

6. Administração Básica do Banco de Dados PostgreSQL

O PostgreSQL é utilizado pela aplicação para armazenar com segurança os logs de auditoria e os acessos dos operadores do painel web.

Acesso ao Prompt e Comandos Importantes

# Acessar a base de dados da aplicação no PostgreSQL
sudo -u postgres psql -d sambacore4_db
Comando / Query Função / Descrição
\dt Lista todas as tabelas criadas no banco da aplicação (operadores, logs, sessões).
\d nome_tabela Exibe a estrutura detalhada e colunas de uma tabela específica.
SELECT * FROM operadores; Consulta e exibe todos os operadores com acesso ao painel.
\q Encerra a sessão e sai do prompt do PostgreSQL.

7. Procedimento de Segurança: Alteração da Senha do Banco PostgreSQL

Por padrão, a instalação automatizada define as seguintes credenciais de banco de dados:

  • Usuário do Banco: sambacore
  • Banco de Dados: sambacore4_db
  • Senha Padrão: dominus7even
⚠️ AVISO IMPORTANTE DE SEGURANÇA:
Em ambientes de produção, é fundamental alterar a senha padrão (dominus7even) para garantir a integridade dos dados e impedir acessos não autorizados.

Passo 1: Alterar a Senha Dentro do PostgreSQL

Execute o comando abaixo no terminal do servidor Linux para modificar a senha do usuário sambacore diretamente no gerenciador do PostgreSQL (substitua SuaNovaSenhaSegura123! pela sua nova senha):

sudo -u postgres psql -c "ALTER USER sambacore WITH PASSWORD 'SuaNovaSenhaSegura123!';"

Passo 2: Atualizar a Senha no Arquivo de Serviço Systemd (`sambacore.service`)

Como a aplicação obtém as credenciais através de variáveis de ambiente gerenciadas pelo systemd, você deve atualizar o arquivo de serviço localizado em /etc/systemd/system/sambacore.service:

1. Abra o arquivo no editor de texto:

sudo nano /etc/systemd/system/sambacore.service

2. Localize a linha contendo a variável Environment="DB_PASS=..." e atualize para a nova senha:

# Altere a linha abaixo:
Environment="DB_PASS=dominus7even"

# Para a sua nova senha:
Environment="DB_PASS=SuaNovaSenhaSegura123!"

Passo 3: Atualizar a Senha no Script Instalador (`install.sh` / `installsmbc4.sh`)

Caso precise reexecutar a instalação ou realizar novos deploys no futuro, atualize a variável DB_PASS dentro do script de instalação:

# Edite o script de instalação
nano installsmbc4.sh

# Altere a linha correspondente:
DB_PASS="SuaNovaSenhaSegura123!"

Passo 4: Recarregar as Configurações e Reiniciar o Serviço

Por fim, recarregue as configurações do daemon systemd e reinicie o serviço da aplicação para aplicar as alterações:

sudo systemctl daemon-reload
sudo systemctl restart sambacore
sudo systemctl status sambacore

8. Gerenciamento de Serviços e Processos

Gerenciamento Padrão via Service (`systemd`)

sudo systemctl stop sambacore    # Interrompe o funcionamento do painel
sudo systemctl start sambacore   # Inicia o serviço da aplicação
sudo systemctl status sambacore  # Exibe o estado atual do serviço

Encerramento Forçado do Processo (`killall python3`)

Em cenários de exceção onde a aplicação venha a travar ou prender requisições pendentes, utilize o comando:

sudo killall -9 python3
Para que serve encerrar o processo Python forçadamente?
1. Desalocação de Portas: Libera imediatamente a porta de rede utilizada pelo servidor web.
2. Desbloqueio de Conexões: Destrava conexões que tenham ficado presas em deadlock com a base LDAP do Active Directory ou banco de dados.
3. Reinicialização Limpa: Permite reiniciar o serviço sem resíduos de memória através do comando systemctl start sambacore.

9. Conexão Segura: HTTPS vs. Porta 5000 (HTTP)

A utilização da porta 5000 em HTTP convencional transmite dados administrativos e credenciais corporativas em texto simples pela rede local, o que representa um risco de segurança. Por essa razão, a arquitetura do SambaCore4 desabilita o acesso HTTP na porta 5000 e canaliza todas as requisições para a Porta 8443 com HTTPS criptografado via Proxy Reverso Nginx (SSL/TLS).
